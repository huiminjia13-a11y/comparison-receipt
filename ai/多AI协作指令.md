# 多AI协作指令

仓库就是中转站。所有 AI 都从这里取活、往这里交活；慧敏只在一个地方下指令。

## 1. 角色分工

| 角色 | 负责 | 不做 |
|---|---|---|
| **海底捞（总指挥）** | 接慧敏的指令，拆成小任务写进 `ai/TASKS.md`；指定执行者；验收结果、上线后试玩、更新 README | 不直接大改代码 |
| **Hermes（执行）** | 本机脚本、文件整理、小改动、跑命令验证 | 不改任务分配 |
| **Qstar（执行）** | 文案、交互、样式类开发 | 不改任务分配 |
| **Codex（执行）** | 功能开发、修 bug、重构、测试 | 不改任务分配 |

谁做哪条任务，以 `ai/TASKS.md` 里的「执行者」字段为准。

## 2. 仓库约定

```
README.md          项目现状（海底捞维护）
ai/多AI协作指令.md   本文件
ai/TASKS.md        任务队列（唯一的派活入口）
ai/LOG.md          交接日志（每次完工追加一条）
```

### 任务格式（写在 ai/TASKS.md）

```
## T-编号 标题
- 状态：待办 / 进行中 / 待验收 / 完成
- 执行者：Hermes / Qstar / Codex
- 目标：要做成什么样
- 验收：怎么算做完
- 备注：限制、相关文件
```

### 开工前

1. `git pull` 拿最新。
2. 读 `README.md` 和 `ai/TASKS.md`。
3. 只领执行者是自己、状态为「待办」的任务，改成「进行中」并提交，防止撞车。

### 完工后

1. 代码改动单独开分支 `ai/T-编号`，提交后合并或开 PR。
2. 任务状态改成「待验收」。
3. 在 `ai/LOG.md` 追加：

```
### T-编号 · 执行者 · 日期
- 结果：做完了什么 / 没做完的原因
- 改动摘要：改了哪些文件，一两句说明
- 待办：遗留问题、建议下一步
```

4. 提交信息格式：`[T-编号] 执行者: 一句话说明`。

### 规则

- 一次只领一条任务，做不了就写进 LOG 并把状态退回「待办」。
- 不删别人的记录，不改别人在做的任务。
- 遵守项目底线：票面只存本机、分享默认打码、统计只记匿名次数、猫是橘猫、标题不改。

## 4. 慧敏的最小操作

1. **只跟海底捞说要什么。** 海底捞拆好任务写进 `ai/TASKS.md`。
2. **叫执行者开工。** 打开 Hermes / Qstar / Codex，贴上对应开场白（之后只需说一句「去仓库领活」）。
3. **等海底捞验收。** 海底捞读 `ai/LOG.md`、试玩线上版，告诉你过没过；没过就自动追加返工任务。

你不用自己搬运文件或转述结果，一切以仓库为准。
